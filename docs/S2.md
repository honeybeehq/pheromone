# S2 as the hub/cloud event log (assessed 2026-08-20)

**Bottom line: S2 (s2.dev) is almost exactly the "segmented append log → object storage
behind a storage trait" growth path in ARCHITECTURE.md, bought instead of built. Adopt it as
the first non-SQLite implementation of the event-log trait for hub and cloud mode, and as the
trail-network transport. Keep SQLite for the local trail. S2 is the log; pher stays the
brain — nothing in the cascade moves.**

## What S2 is (from their docs, 2026-08-20)

- Account → **basins** (global namespace, like buckets) → **streams** (ordered, durable
  record sequences) → **records** (headers + body). Records ≤ 1 MiB; batches ≤ 1000
  records / 1 MiB; 100 MiB/s append per stream; unlimited basins/streams/tokens.
- **Backed by S3.** Chunks (write-ahead log) + segments on object storage; "appends are only
  acknowledged when records are durable in a chunk", multi-zone. Two storage classes:
  `standard` (S3 Standard chunk bucket) and `express` (quorum of three S3 Express zonal
  buckets, "much lower latency"). Same durability; class only changes append latency. No
  latency numbers are published anywhere in the docs.
- Retention: age-based (default 7d) or **infinite**; explicit trim; expired records linger
  "on the order of minutes". Timestamping `client-prefer` (default) / `client-require` /
  `arrival`. Seq numbers per stream; atomic batches.
- Concurrency: `match_seq_num` (optimistic) and `fencing_token` (pessimistic). Reads: from
  seq, from timestamp, or tail; live via SSE, long-poll (`?wait=`), or **S2S** (binary over
  HTTP/2). SDKs: TS, Python, Go, Rust (Producer API: batching/ordering/retries/backpressure;
  read sessions). Also `create_stream_on_append/read`, `delete_on_empty` + `min_age_secs`.
- Pricing: $0.05/GiB write (standard), $0.075 (express); $0.05/GiB-month stored; $0.05/GiB
  private read, $0.10 internet read; hourly metering of basins/streams/tokens; sessions
  metered as one op/minute. 99.99% availability SLO. SOC 2, HIPAA BAA.
- **s2-lite**: MIT, single binary, SlateDB on S3 / local disk / memory, implements the core
  S2 API — same SDKs/CLI/Studio. Self-host and CI emulator. This is the no-lock-in hedge and
  the on-tailnet deployment path.

## Mapping onto pheromone

| Pher | S2 |
|---|---|
| tenant/org (ROADMAP open question #6) | basin |
| a trail (one pherd), or one stream per node within a tenant | stream |
| log `seq`; `listen --after N`; hub-side `--cursor` | seq; read session from seq |
| `since <lookback>` replay | read from timestamp |
| evaporation / `PHER_RETENTION` | retention age / trim; infinite for archive |
| envelope `ts` | `client-prefer` timestamp |
| single writer per trail | `fencing_token` |
| bridge: durable filtered pull over `/listen` | read session / tail on the upstream stream |
| grants / leaf tokens | per-stream scoped access tokens |
| ephemeral leaf (`pherd leaf --parent`) | `create_stream_on_append` + `delete_on_empty` |

What stays in SQLite regardless: subscriptions, cursors, deliveries index, `expect` timers,
FTS5, vectors, verdict cache, forwarded-dedup window. Only **event bodies** move (optionally
also a deliveries/verdicts audit stream, append-only, for `why` across restarts and nodes).

## Where it earns its keep

1. **Hub mode.** `store = s2` on the hub pherd: infinite replay, `why-not` against
   arbitrarily old events, no local GC pressure, no disk. Cost at agent volumes is noise
   (1 KB × 1M events/day ≈ 1 GiB/day ≈ $0.05/day to write, $1.50/month/GiB retained).
2. **Trail-network transport.** Leaves append to a stream; hub and bridges read it. Replaces
   pherd↔pherd HTTP (`http` sink outbox, `/listen` pull) for any node that can reach S2 or
   an s2-lite on the tailnet. Removes most of the slice-6 satellite-relay / public-ingress
   work for those nodes. Ordering per stream; correlation/threads untouched (they're in the
   envelope).
3. **Pheromone Cloud.** Hosted pherds run the cascade (tiers 3–4 with budgets) over
   per-tenant basins. Tenant boundary, token scoping, retention, encryption at rest, and the
   compliance paperwork come for free. Answers ROADMAP #6: per-tenant basin, per-node stream.

## What it is not

- Not the local trail. `emit` today is µs–ms and crash-safe on disk; S2 `standard` is an S3
  ack (hundreds of ms), `express` lower but unpublished. S2 never sits in the laptop hot path.
- Not a matcher. Filter-at-source still runs tiers 1–2 at the leaf; S2 carries events, not
  subscriptions.
- Not a dedup layer. No idempotency key on append; event-id admission dedup on ingest (which
  bridges already do) and `deliveryId` dedup on delivery stay as they are.

## Design decisions this forces

- **Ack semantics in cloud mode.** Two coherent options: (a) S2 *is* the WAL — `emit` acks
  after S2 ack, `express` class, Producer API batching; (b) local WAL then outbox-ship, as
  the `http` sink does today — local ack latency, eventual S2 durability. Leaf nodes are
  (a) (they have no local durability anyway); hubs default to (b) with (a) as config.
- **Stream cardinality.** One stream per (tenant, node) — scoped tokens, cheap fan-in, still
  few enough to meter. Subject filtering stays in the subject trie, not in stream layout.
  `delete_on_empty` for ephemeral leaves.
- **Seq space.** The hub's log `seq` becomes (stream, s2_seq); `listen --after` and cursors
  carry a stream id. Bridges re-ingest into the local seq space as today (hops++, same id).
- **Read cost.** Keep hub pherds in the same region as the basin (private read) for
  replay-heavy flows; internet read is 2×.
- **Hedge.** Every S2 integration test runs against s2-lite. If S2 the company goes away,
  s2-lite on our own bucket is the same code path.

## The trait

`Db::append_event / max_seq / events_after / events_since_ts / gc` in `crates/pher/src/db.rs`
is already the implicit interface. Lift it:

```rust
pub trait EventLog: Send + Sync {
    /// Append; returns the assigned seq. Local impl assigns; S2 impl returns S2's seq.
    fn append(&self, event: &Envelope) -> anyhow::Result<u64>;
    fn append_batch(&self, events: &[Envelope]) -> anyhow::Result<u64>; // last seq
    fn max_seq(&self) -> anyhow::Result<Option<u64>>;
    fn read_after(&self, after: Option<u64>, limit_last: Option<usize>)
        -> anyhow::Result<Vec<(u64, Envelope)>>;
    fn read_since_ts(&self, ts: &str) -> anyhow::Result<Vec<(u64, Envelope)>>;
    fn by_id(&self, id: &str) -> anyhow::Result<Option<Envelope>>;   // index-backed
    fn tail(&self, after: u64) -> anyhow::Result<Box<dyn Iterator<Item = (u64, Envelope)>>>;
    fn trim_before(&self, ts: &str) -> anyhow::Result<()>;            // gc / retention
}
```

`SqliteEventLog` = today's code. `S2EventLog` = `s2-sdk` (Rust) against
`s2://<basin>/<node>`; `by_id` stays in the SQLite index (id → (stream, seq)). Verdicts,
vectors, deliveries, forwarded window are untouched by the trait.

## Plan

1. `EventLog` trait + `SqliteEventLog`; zero behaviour change; existing tests green.
2. `S2EventLog` behind a `pher-store-s2` feature; CI runs s2-lite in a job. `[store] kind =
   "s2"`, basin/stream/token/class in `pheromone.toml`; `PHER_S2_TOKEN` via Hem.
3. Hub mode: cursors carry stream id; `listen --after` / `--cursor` unchanged at the CLI.
4. Leaf append-direct-to-S2 (filter-at-source unchanged) and bridge-from-S2-stream; measure
   against the `http` outbox drill (hub down → up, exactly once).
5. Cloud: per-tenant basin provisioning, token issuance mapped to grants.
